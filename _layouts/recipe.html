--- layout: default --- {%- comment -%} One pass, two outputs. Everything below is derived from the recipe's front matter and then used twice: once for the schema.org/Recipe JSON-LD an importer reads, once for the page a person reads. Deriving both from the same variables is what stops the two from drifting apart. Two behaviours here exist purely because of how importers work: * URLs in the JSON-LD are absolute, because the importer fetches the structured data away from the page it came from; * every step restates its appliance session, because importers read each step in isolation. {%- endcomment -%} {%- comment -%} Ingredients: flatten the display groups into one list. `recipeIngredient` and `supply` are both built from this, so a group heading can never leak into the structured data. {%- endcomment -%} {%- assign flat_ingredients = "" | split: "" -%} {%- for group in page.ingredients -%} {%- assign flat_ingredients = flat_ingredients | concat: group.items -%} {%- endfor -%} {%- comment -%} Images: `image` accepts one path or a list. Normalise to a list of absolute URLs — importers drop a relative path, since it resolves against nothing once the JSON-LD has been fetched on its own. {%- endcomment -%} {%- assign image_input = "" | split: "" -%} {%- if page.image -%} {%- if page.image.first -%} {%- assign image_input = page.image -%} {%- else -%} {%- assign image_input = page.image | split: "|" -%} {%- endif -%} {%- endif -%} {%- capture images_csv -%} {%- for img in image_input -%}{{ img | absolute_url }}{%- unless forloop.last -%},{%- endunless -%}{%- endfor -%} {%- endcapture -%} {%- assign recipe_images = images_csv | strip | split: "," -%} {%- comment -%} Authors: a recipe may name its own, as a string or a list; otherwise both maintainers are credited.
